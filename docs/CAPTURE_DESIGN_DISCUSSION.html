為什麼不保留每個階段？還能更精簡嗎？
你的質疑成立：先前語音範例的原音檔、note.md、source.json、transcript.txt、polished.md 五檔，適合需要除錯或逐階段比對的情境，對個人原文與摘要需求太多。新版預設移除獨立 source.json 與 polished.md；note.md 前置欄位放來源 ID、時間、管道、作者聲明、檔案關係與清理狀態。模型中間輸出與轉碼檔只作短期處理，不當永久內容檔案。
另一個選擇是把原文與摘要合併成單一 note.md，文字只需一檔、語音加音檔共兩檔；代價是全文與摘要無法分開刪除或替換。考慮你希望每個檔案可獨立或批次刪除，本稿建議採兩至三檔的分離方式。需要除錯時才另行開啟有期限的診斷紀錄。
「可追溯」靠穩定來源 ID 與檔案關係，不靠複製每個階段。服務另保留小型持久化管理紀錄，記錄檔案 ID、處理與刪除狀態，支援重試和去重；不在其中再複製全文、音訊或所有模型輸出，也不為每筆收件另產生一個 JSON 檔。

原檔先保存，摘要失敗怎麼辦？

這些檔案如何成為 Atlas 的 raw？

後續版本再處理什麼？
